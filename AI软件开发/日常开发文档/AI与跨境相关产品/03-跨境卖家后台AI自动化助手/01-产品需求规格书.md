> **文档版本**：V1.0  
> **编写日期**：2026-07-19  
> **状态**：MVP 立项

---

## 1. 文档概述

### 1.1 编写目的

定义「跨境卖家店铺智能巡检与广告优化辅助系统 V1.0」（代号 SellerGuard）的产品需求。本系统 **本地部署**，通过浏览器 CDP 连接用户自有 Chrome，执行卖家后台的只读巡检任务，生成广告与 Listing 健康报告，并提供 AI 优化建议。强调限速熔断，杜绝违规自动化。

### 1.2 术语定义

| 术语 | 定义 |
|------|------|
| CDP | Chrome DevTools Protocol，浏览器远程调试协议 |
| 巡检 | 定时或手动触发的后台数据采集任务 |
| 熔断 | 检测到异常（验证码、频率限制）时立即停止所有自动化 |
| Profile | Chrome 用户配置目录，隔离不同店铺登录态 |
| 只读模式 | 仅采集数据，不执行任何写操作 |
| ACOS | Advertising Cost of Sales，广告销售成本占比 |

## 2. 产品背景与目标

### 2.1 市场背景

跨境卖家每日需登录 Amazon/TikTok 等后台查看广告报表、Listing 状态、库存与评价。数据分散、重复劳动多；云端 RPA 将 Cookie 上传存在账号安全风险。本地部署 + CDP 方案可在用户本机执行，密钥不出境。

### 2.2 产品愿景

成为卖家「店铺健康仪表盘」：每日自动巡检、异常秒级告警、AI 可读报告，**零误操作**。

### 2.3 业务目标（V1.0 MVP）

| 目标 | 量化指标 |
|------|----------|
| 巡检成功率 | > 95% |
| 日报时效 | 每日 8:00 前生成 |
| 熔断可靠性 | 触发后 100% 停止写操作 |
| 部署成功率 | 标准环境 > 90% |
| 种子客户 | 3 家本地部署试用 |

### 2.4 成功标准

1. 用户 30 分钟内完成本地 Docker 部署并连接 Chrome。  
2. SP 广告报表（_campaign 级）每日自动采集并入库。  
3. Listing suppressed/低库存异常推送至钉钉。  
4. 模拟验证码场景，系统在 3 秒内熔断并告警。

## 4. 用户场景

### 4.1 场景一：每日广告日报

**角色**：广告投手  
**前置**：Amazon 卖家账号已在 Chrome Profile A 登录；系统已配置每日 7:00 巡检。  
**流程**：
1. 7:00 调度器触发「SP 广告报表」任务。  
2. Agent 通过 CDP 打开广告控制台，按预设选择日期范围「昨日」。  
3. 采集 Campaign 名称、花费、销售额、ACOS、点击量、转化率。  
4. 数据写入本地 PostgreSQL。  
5. 7:30 LLM 生成摘要：「昨日 ACOS 12.3%，较 7 日均值升 2.1pp，主要因 Campaign X 花费激增…」  
6. 8:00 钉钉推送日报链接。  
7. 投手登录本地 Web 控制台查看图表与建议。

**验收**：数据与后台手工导出一致（误差 < 1%）；摘要有 actionable 建议。

### 4.2 场景二：Listing 异常告警

**角色**：运营主管  
**流程**：
1. 每 4 小时执行 Listing 状态巡检。  
2. 发现 ASIN B08XXX 状态变为「Suppressed」，原因「主图不符合要求」。  
3. 系统标记 P1 异常，立即推送告警。  
4. 主管点击查看截图快照（巡检时自动截取）。  
5. 主管手工修复后，下次巡检自动恢复为正常。

**验收**：异常检出延迟 < 4 小时；截图可查看。

### 4.3 场景三：验证码熔断

**角色**：系统（自动）  
**流程**：
1. 巡检过程中页面出现 CAPTCHA 或「异常活动」提示。  
2. 检测器 3 秒内识别（DOM + 视觉特征）。  
3. 立即终止当前任务，标记全局熔断状态 24 小时。  
4. 所有写操作（若有）锁定；只读任务也暂停。  
5. 推送紧急告警：「请人工登录处理验证码后，在控制台解除熔断」。  
6. 用户人工处理后点击「解除熔断」，系统恢复。

**验收**：熔断后无后续自动化请求；日志记录完整。

### 4.4 场景四：多店铺 Profile 隔离

**角色**：管理员  
**流程**：
1. 配置 Profile A（美国店）、Profile B（欧洲店），不同 Chrome 用户目录。  
2. 任务指定 Profile，互不串号。  
3. 审计日志记录每次任务使用的 Profile。

**验收**：两店铺数据隔离；无交叉登录。

## 6. 非功能需求

### 6.1 安全与合规

- **数据本地化**：所有报表、截图、日志存本机，默认不上云  
- **凭证**：不存储 Amazon 密码；依赖 Chrome 已有登录态  
- **合规**：遵守 Amazon/TikTok ToS；文档明确禁止刷单等操作  
- **审计**：所有 Agent 动作可回放（截图+日志）  

### 6.2 性能

| 指标 | 要求 |
|------|------|
| 单次 SP 报表采集 | < 5 分钟 |
| 看板加载 | < 2s |
| 熔断响应 | < 3s |

### 6.3 可靠性

- 任务失败自动重试 2 次（指数退避）  
- 数据库每日本地备份
