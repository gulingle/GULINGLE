# 03-实战运营手册

> **软件名称**：跨境电商多平台智能商品运营管理系统 V1.0  
> **适用版本**：V1.0 MVP  
> **最后更新**：2026-07-19

---

## 1. 手册目的与适用范围

本手册供 **运营专员、运营主管、客成实施、技术支持** 在日常工作中直接执行。覆盖日/周/月 SOP、KPI 考核、角色职责、异常处理与验收标准。

**适用场景**：
- SaaS 试用客户 onboarding
- 私有化部署客户交付
- 内部运营团队日常使用

## 3. KPI 指标体系

### 3.1 运营效率 KPI

| KPI | 计算公式 | 日目标 | 周目标 | 月目标 | 数据来源 |
|-----|----------|--------|--------|--------|----------|
| 上架时效 | 采集确认→发布成功耗时（中位数） | < 6h | < 5h | < 4h | publish_records |
| 日刊登量 | 成功发布 SKU 数 | ≥ 5/人 | ≥ 25/人 | ≥ 100/人 | publish_records |
| AI 采纳率 | 采用 AI 字段数 / AI 生成字段总数 | ≥ 55% | ≥ 60% | ≥ 65% | ai_generations |
| 一次通过率 | 首次审核通过 / 提交总数 | ≥ 70% | ≥ 75% | ≥ 80% | drafts |
| 刊登成功率 | 成功 / 刊登任务总数 | ≥ 93% | ≥ 95% | ≥ 97% | tasks |

### 3.2 质量 KPI

| KPI | 计算公式 | 目标 |
|-----|----------|------|
| 禁词拦截率 | 拦截次数 / 提交审核次数 | 100% 拦截（零漏放） |
| 刊登后下架率 | 7 日内因信息问题下架数 / 刊登数 | < 2% |
| 版本回滚率 | 已发布后修改重发 / 已发布总数 | < 10% |

### 3.3 系统健康 KPI

| KPI | 目标 | 责任人 |
|-----|------|--------|
| 采集解析成功率 | > 90% | 技术支持 |
| 任务队列积压 | < 50 待处理 | 技术支持 |
| API 可用性 | > 99.5% | 技术支持 |
| 库存同步延迟 | < 15 min | 技术支持 |

## 4. 每日 SOP（Daily）

### 4.1 运营专员 — 日流程（建议 09:00–18:00）

| 时间 | 步骤 | 操作说明 | 产出物 | 异常处理 |
|------|------|----------|--------|----------|
| 09:00–09:15 | 晨会签到 | 查看任务中心昨日失败任务 | 失败清单 | 见 §6.1 |
| 09:15–09:30 | 库存巡检 | 打开「库存看板」，筛选低库存 SKU | 补货清单 | 同步延迟 > 30min → 报技术支持 |
| 09:30–12:00 | 采集与草稿 | 按选品表执行 URL/表格采集；触发 AI 文案 | 待审草稿 ≥ 3 条 | 解析失败 → 手工录入 |
| 12:00–12:30 | 午休前提交 | 完成编辑的草稿提交审核 | 提交记录 | - |
| 14:00–15:30 | 审核反馈处理 | 处理驳回草稿，修改后重提 | 重提记录 | 驳回 > 2 次 → 请示主管 |
| 15:30–17:00 | 刊登执行 | 主管已审草稿执行刊登 | 刊登成功记录 | 见 §6.2 |
| 17:00–17:30 | 订单导出 | 导出当日新订单 CSV 交发货 | 订单 CSV | 订单缺失 → 手动同步 |
| 17:30–18:00 | 日结填报 | 填写日报模板（见 4.3） | 运营日报 | - |

### 4.2 运营主管 — 日流程

| 时间 | 步骤 | 操作 |
|------|------|------|
| 09:30 | 审核队列 | 处理待审草稿，目标 2h 内清空上午提交 |
| 11:00 | 质量抽检 | 随机 2 条已审草稿，检查禁词与平台规则 |
| 14:00 | 二次审核 | 处理上午驳回重提 |
| 16:00 | 刊登授权 | 确认当日刊登任务无积压 |
| 17:30 | KPI 看板 | 核对当日刊登量、成功率、采纳率 |

## 5. 每周 SOP（Weekly）

### 5.1 周一 — 周计划会（10:00，60min）

**参与人**：主管、全体运营、客成（如有客户）

| 议程 | 时长 | 内容 |
|------|------|------|
| 上周复盘 | 20min | 周 KPI 达成、失败 Top3 原因 |
| 本周目标 | 15min | 刊登量、新平台、新店铺目标 |
| 选品对齐 | 15min | 本周重点 SKU 清单 |
| 风险同步 | 10min | 平台政策、授权过期、库存风险 |

**周目标表示例**：

| 指标 | 目标 | 责任人 |
|------|------|--------|
| 周刊登量 | 50 SKU | 全员 |
| AI 采纳率 | ≥ 60% | 专员 |
| 刊登成功率 | ≥ 95% | 主管 |
| 新店铺授权 | 1 个 TikTok 店 | 管理员 |

### 5.2 周三 — 质量复盘（15:00，30min）

1. 导出本周「已驳回」草稿，分类原因：禁词 / 信息不全 / 图片 / 其他  
2. 更新禁词库（如有新模式）  
3. 更新 AI Prompt 反馈（提交给 AI 工程师）  
4. 抽检 5 条已发布 Listing 与平台实际页面对比  

### 5.3 周五 — 周结与数据导出（16:00，45min）

| 步骤 | 操作 |
|------|------|
| 1 | 导出周 KPI 报表（系统看板 → 导出） |
| 2 | 填写《周运营复盘表》 |
| 3 | 清理「已归档」草稿 > 90 天（管理员） |
| 4 | 检查店铺授权过期列表 |
| 5 | 发送客户周报（客成，SaaS 客户） |

**周复盘表**：

| 指标 | 目标 | 实际 | 差距 | 改进动作 |
|------|------|------|------|----------|
| 刊登量 | | | | |
| 采纳率 | | | | |
| 成功率 | | | | |
| 上架时效 | | | | |

## 6. 每月 SOP（Monthly）

### 6.1 月初（1–3 日）— 月度规划

| 步骤 | 负责人 | 内容 |
|------|--------|------|
| M1 | 主管 | 制定月刊登目标、平台拓展计划 |
| M2 | 管理员 | 检查全部店铺授权状态、续费 |
| M3 | 技术支持 | 系统版本检查、备份验证 |
| M4 | 客成 | SaaS 客户续费沟通 |

### 6.2 月中（15 日）— 中期检视

- 月 KPI 完成率是否 ≥ 45%（时间过半）  
- AI 采纳率趋势；若连续 2 周 < 55%，启动 Prompt 优化专项  
- 盘点失败任务类型分布  

### 6.3 月末（最后 3 日）— 月结

| 步骤 | 产出 |
|------|------|
| 导出月度运营报表 | Excel |
| 客户 ROI 测算（节省人时 × 时薪） | 月报 PPT |
| 禁词库/映射模板版本归档 | Git 标签 |
| 软著/商务材料更新（如有新功能） | 文档 |

### 6.4 月度验收会议（月末，90min）

**参与人**：主管、管理员、客成、产品、技术

**议程**：
1. 月 KPI 达成评审  
2. 客户反馈汇总（NPS、工单）  
3. 下月功能优先级确认  
4. 风险清单更新

## 7. 异常处理手册

### 7.1 采集失败

| 现象 | 可能原因 | 处理步骤 | 升级条件 |
|------|----------|----------|----------|
| 解析字段为空 | 反爬/页面结构变更 | 1. 重试 2. 换 URL 3. 手工录入 | 同 URL 3 次失败 |
| 任务一直 pending | Worker 宕机 | 联系技术支持重启 Worker | 积压 > 1h |
| 图片下载失败 | 外链失效 | 本地上传图片 | - |

**升级**：技术支持 → 研发（解析器热修）

### 7.2 刊登失败

| 错误码 | 含义 | 处理 |
|--------|------|------|
| `INVALID_CREDENTIALS` | 授权过期 | 管理员重新 OAuth |
| `CATEGORY_NOT_FOUND` | 类目映射错误 | 修正 category_id |
| `IMAGE_TOO_SMALL` | 图片尺寸不符 | 替换符合规格图片 |
| `DUPLICATE_SKU` | SKU 重复 | 修改 sku_code 或走更新接口 |
| `PLATFORM_API_ERROR` | 平台 5xx | 等待 30min 重试，最多 3 次 |

**熔断规则**：同一店铺连续 5 次刊登失败 → 暂停该店铺刊登任务，主管介入。

### 7.3 AI 生成质量差

| 现象 | 处理 |
|------|------|
| 标题同质化 | 换 tone；增加竞品差异约束 |
| 禁词反复出现 | 反馈 AI 工程师；临时加禁词 |
| 与商品不符 | 检查采集数据完整性；补充卖点备注 |
| Token 超限 | 管理员提升配额或换小模型 |

### 7.4 库存/订单不同步

| 现象 | 处理 | SLA |
|------|------|-----|
| 库存 30min 未更新 | 手动触发同步 | 技术支持 2h 响应 |
| 订单缺失 | 检查授权 scope；手动拉取 | 4h 修复 |
| 数量明显错误 | 对比平台后台；提工单 | 24h 根因分析 |

### 7.5 安全事件

| 事件 | 立即动作 |
|------|----------|
| 疑似账号泄露 | 吊销店铺授权；强制改密 |
| 异常批量刊登 | 暂停租户；查 audit_logs |
| 禁词漏放导致下架 | 复盘审批链；加固规则 |

## 8. 客户 Onboarding SOP（客成）

### 8.1 试用启动（D0–D3）

| 天 | 动作 | 验收 |
|----|------|------|
| D0 | 开通租户；创建管理员账号 | 可登录 |
| D1 | 完成 1 个店铺授权（Amazon 或 TikTok） | 授权状态 active |
| D2 | 培训 2h：采集→AI→审核→刊登 | 客户完成 1 条刊登 |
| D3 | 检查首条刊登成功；收集反馈 | ASIN/product_id 可见 |

### 8.2 试用期（D4–D14）

- 每周 1 次 30min 答疑  
- 第 7 天 KPI 检查：刊登 ≥ 10 条  
- 第 14 天试用评审：决定是否付费  

### 8.3 正式客户交付清单

- [ ] 全部目标店铺授权完成  
- [ ] 禁词库导入（客户自定义）  
- [ ] 平台字段映射模板配置  
- [ ] 3 名运营完成培训考核  
- [ ] 运维联系人建立（技术支持群）  
- [ ] 签署数据安全协议

## 9. 培训与考核

### 9.1 新人培训（2 小时）

| 模块 | 时长 | 内容 |
|------|------|------|
| 1 | 30min | 系统概览、角色权限 |
| 2 | 30min | 采集与草稿操作实操 |
| 3 | 30min | AI 生成与审核要点 |
| 4 | 30min | 刊登与异常处理 |

### 9.2 上岗考核标准

| 考核项 | 标准 |
|--------|------|
| 独立完成 URL 采集 | 1 次成功 |
| AI 文案编辑并提交 | 1 次 |
| 识别禁词并修改 | 3/3 正确 |
| 模拟刊登失败处理 | 说出 3 种错误处理 |
| 填写运营日报 | 格式正确 |

**通过线**：5 项中 ≥ 4 项合格。

## 10. 验收标准（运营侧）

### 10.1 日验收

- [ ] 任务中心无超过 24h 的 failed 未处理任务  
- [ ] 低库存 SKU 已登记补货清单  
- [ ] 当日刊登成功率 ≥ 93%  

### 10.2 周验收

- [ ] 周刊登量达标  
- [ ] AI 采纳率 ≥ 60%  
- [ ] 周复盘表已提交  
- [ ] 零禁词漏放事件  

### 10.3 月验收

- [ ] 月 KPI 达成率 ≥ 85%  
- [ ] 客户 NPS ≥ 40（SaaS）  
- [ ] 系统可用性达标  
- [ ] 月度报表已归档
