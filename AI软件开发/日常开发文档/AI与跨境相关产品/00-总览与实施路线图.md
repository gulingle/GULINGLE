# AI × 跨境产品总览与实施路线图

## 1. 战略定位

面向中国跨境卖家与出海品牌，构建 **「情报 → 选品 → 内容 → 上架 → 投放 → 客服 → 复盘」** 全链路 AI 软件矩阵。  
不做空泛聊天机器人，只做能进入真实运营日流程、可计量 ROI 的工具。

### 1.1 目标客户

| 客户分层 | 特征 | 优先产品 |
|----------|------|----------|
| 个人/小团队卖家 | 1–5 人，多平台铺货 | 02 成片、01 运营中台、06 选品 |
| 成长型卖家 | 10–50 人，有运营专岗 | 01/03/05/07/08 |
| 品牌/独立站 | DTC + 平台双轨 | 04/05/09/10 |
| 代运营/服务商 | 多店铺代管 | 01/03/07/10（私有化） |

### 1.2 核心价值链

```text
06 选品情报 ──► 07 合规审查 ──► 01 商品运营中台 ──► 04 独立站 / 平台刊登
                      │                    │
                      ▼                    ▼
                 09 视觉工厂 ──► 02 短视频成片 ──► 08 达人合作
                                           │
                                           ▼
                              05 AI 客服 ←── 03 后台自动化
                                           │
                                           ▼
                                    10 多 Agent 总控
```

## 2. 统一技术原则（全产品共用）

| 原则 | 要求 |
|------|------|
| 本地/私有化优先 | 卖家密钥、Cookie、商品库默认客户侧可控 |
| 多租户 | 店铺级隔离：数据、任务、配额、审计日志 |
| 人机协同 | AI 建议默认「待确认」；高风险动作需二次确认 |
| 可观测 | 任务状态、Token 消耗、成功率、人工干预率全埋点 |
| 平台合规 | 自动化须遵守平台 ToS；提供节奏限制与熔断 |
| 模型可切换 | 兼容 OpenAI / Claude / DeepSeek / 通义 / 本地 Ollama |

### 2.1 建议统一技术栈

| 层 | 选型 |
|----|------|
| 前端 | React / Next.js + Ant Design |
| 后端 | Go (Gin) 或 NestJS / FastAPI |
| 任务队列 | Redis + BullMQ / Asynq |
| 数据库 | PostgreSQL + Redis |
| 对象存储 | S3 兼容 / 本地 MinIO |
| 工作流 | n8n（编排）+ 自研业务服务 |
| AI | 统一 LLM Gateway（自研） |
| 部署 | Docker Compose → K8s |

## 3. 统一运营指标体系

| 指标 | 定义 | 健康线 |
|------|------|--------|
| 上架时效 | 从选品确认到 Listing 发布 | < 4 小时（人工审核后） |
| AI 采纳率 | 运营确认采用 AI 建议的比例 | > 60% |
| 成片可用率 | 一键成片无需大改即可发布 | > 50% |
| 客服一次性解决率 | AI 会话无需转人工 | > 40%（冷启动）→ 70% |
| 合规拦截准确率 | 命中真实风险 / 总拦截 | > 85% |
| 自动化任务成功率 | 后台任务完整成功 | > 95% |
| 月留存 | 付费客户次月续费 | > 80% |

## 4. 90 天实战落地计划

### Phase A（Day 1–30）：能演示、能收费

| 周 | 交付 |
|----|------|
| W1 | 统一账号/店铺模型、LLM Gateway、任务中心骨架 |
| W2 | **01** 采集→草稿→AI 文案→人工确认→导出（Amazon + TikTok 先做 1 个） |
| W3 | **02** 单图成片 MVP（脚本+配音+字幕+导出 MP4） |
| W4 | 演示环境、定价页、首批 5 个种子客户试用 |

### Phase B（Day 31–60）：形成闭环

| 周 | 交付 |
|----|------|
| W5–6 | **06** 竞品采集与选品评分；**07** Listing 合规检查接入 01 |
| W7 | **05** 客服 FAQ + 订单查询工具（1 个渠道） |
| W8 | 运营 SOP 固化、周报模板、软著材料初稿（01/02） |

### Phase C（Day 61–90）：扩大壁垒

| 周 | 交付 |
|----|------|
| W9 | **04** 独立站主题 + AI 生成商品页 |
| W10 | **03** 广告巡检只读报告；**08** 达人库与 outreach 草稿 |
| W11 | **09** 主图批产工作流；**10** 用 n8n/自研编排串联 01→02→07 |
| W12 | 私有化安装包、销售 Demo Script、第二批软著提交 |

## 5. 团队最小配置

| 角色 | 人数 | 职责 |
|------|------|------|
| 全栈负责人 | 1 | 架构、核心模块 |

| 后端 + 爬虫/RPA | 1–2 | 任务、平台适配 |
| AI 应用工程师 | 1 | Prompt、评测、质检 |
| 跨境运营顾问（兼职可） | 1 | SOP、验收标准 |
| 商务/客成 | 0.5–1 | 种子客户、续费 |

## 6. 合规与风险红线

1. 不存储明文支付卡号；平台 Cookie 加密保存并可一键吊销。  
2. 浏览器自动化默认限速；触发验证码立即暂停并告警。  
3. 生成内容必须经过禁词/侵权规则（对接 07）。  
4. 客户数据不得用于训练公共模型（合同条款）。  
5. 软著与对外宣传文案避免夸大「全自动无人值守赚钱」。
