# 10-跨境多Agent运营调度中枢

> **软件登记名**：跨境电商多智能体协同运营调度系统 V1.0  
> **产品代号**：OpsOrchestrator / OO-10  
> **版本**：V1.0（文档基线：2026-07）  
> **技术参考**：DeerFlow（多 Agent 协作）、atlas-mercator（工具地图）、n8n（工作流编排）

## 1. 产品定位

**跨境电商运营体系的「总控大脑」**。通过多 Agent 编排 + 统一工具网关 + 审计追溯，将 01–09 号产品串联为可执行、可观测、可回滚的端到端工作流，实现「选品 → 合规 → 上架 → 视觉 → 视频 → 达人 → 投放巡检 → 客服 → 复盘」的协同自动化。

### 1.1 为什么需要 10 号总控

| 问题 | 单点产品局限 | 10 号解法 |
|------|--------------|-----------|
| 流程断裂 | 01/07/09 各开各的界面 | 统一工作流：一步触发多系统 |
| 重复填数 | SKU 信息多次录入 | Agent 上下文共享 + 工具网关 |
| 无法审计 | 不知道 AI 做了什么 | 全链路任务日志 + 人工确认点 |
| 策略难迭代 | 改流程要改代码 | 可视化编排 + Prompt 版本管理 |
| 权限混乱 | 各系统 API Key 分散 | 统一鉴权、配额、熔断 |

### 1.2 产品边界

**做什么：**
- 编排 01–09 的标准工具为 Agent 可调用能力
- 预置跨境运营工作流模板（上新、大促、达人 campaign、巡检）
- 多 Agent 角色：选品顾问、Listing 编辑、合规官、视觉导演、达人媒介、客服主管
- 人机协同闸口：高风险动作必须人工 Approve
- 任务审计、Token 成本、成功率看板

**不做什么：**
- 不重复实现 01–09 的业务逻辑（只做编排与网关）
- 不承诺无人值守全自动盈利
- 不替代 n8n 的全部通用集成（跨境场景优先）

## 3. 预置实战工作流（示例）

| 工作流 ID | 名称 | 串联系统 | 触发方式 |
|-----------|------|----------|----------|

| WF-LISTING-REFRESH | Listing 优化迭代 | 06→07→01 | 销量下滑告警 |
| WF-TIKTOK-CAMPAIGN | TikTok 达人 Campaign | 01→09→02→08 | 营销计划 |
| WF-DAILY-OPS | 每日运营巡检 | 03→05→07 | 定时 08:00 |
| WF-PROMO | 大促备战 | 06→09→01→03→02 | 日历事件 |
