**产品**：跨境电商多智能体协同运营调度系统 V1.0  
**适用对象**：运营主管、各模块运营、架构师、店长  
**文档版本**：V1.0 | 2026-07-19

## 1. 总控定位：10 号如何实战编排 01–09

10 号不是替代各业务系统，而是**把跨境运营的标准动作编排成可重复、可审计、有人机闸口的流水线**。运营主管从「逐个系统操作」变为「启动工作流 + 审批关键节点」。

### 1.1 产品编排矩阵

| 业务目标 | 工作流 | 串联产品 | 人工闸口 |
|----------|--------|----------|----------|
| 新品上架 | WF-NEW-SKU | 06→07→09→01→(04) | 主图审批、发布确认 |
| Listing 优化 | WF-LISTING-REFRESH | 06→07→01 | 文案确认 |
| TikTok 推广 | WF-TIKTOK-CAMPAIGN | 01→09→02→08 | 达人名单、Outreach |
| 每日巡检 | WF-DAILY-OPS | 03→05→07 | 无（只读报告） |
| 大促备战 | WF-PROMO | 06→09→01→03→02 | 素材+价格+脚本 |
| 独立站同步 | WF-DTC-SYNC | 01→07→04 | 页面发布 |
| 客诉升级 | WF-CS-ESCALATE | 05→01→07 | 回复确认 |

## 7. 核心工作流实战手册

### 7.1 WF-NEW-SKU（新品上架）— 最常用

**触发**：06 选品确认 / 主管手动 / Chat「上架 SKU-12345 到 Amazon US」

**时间线（目标 4h 含人工）**：

| 阶段 | 耗时 | 系统 | 人工 |
|------|------|------|------|
| 选品评分 | 2min | 06 | 分数<60 终止 |
| 文案生成 | 5min | 10 Agent + 01 | - |
| 合规预审 | 1min | 07 | 高风险改版 |
| 主图批产 | 15min | 09 | **Gate：审批主图** |
| 写草稿 | 2min | 01 | - |
| 合规终检 | 1min | 07 | - |
| 发布 | 1min | 01 | **Gate：发布确认** |
| 独立站(可选) | 5min | 04 | Gate |

**主管日课**：上午批主图，下午批发布。

### 7.2 WF-TIKTOK-CAMPAIGN

**触发**：营销日历 / 「为 SKU-X 做 TikTok 达人推广」

| 步骤 | 动作 | 负责人 |
|------|------|--------|
| 拉 SKU | 自动 | 10 |
| 场景图批产 | 09 | 视觉运营审批 |
| 样片脚本 | 02 | 内容运营可选审 |
| 达人匹配 | 08 | 媒介运营 **Gate：名单** |
| Outreach 草稿 | 08 | 人工发送 TikTok |
| 创建 Deal | 08 | 媒介跟进 |

### 7.3 WF-DAILY-OPS（无人值守巡检）

- 每日 08:00 自动
- 产出 Markdown 日报 → 钉钉群
- **运营主管只处理 P0**，不阻塞 Run

**P0 定义**：
- 广告花费异常 >50% 波动
- 库存为 0 在售
- 合规复检新增 BLOCKER
- 客服 SLA 超时 >20 单

### 7.4 WF-LISTING-REFRESH

- 触发：销量连续 7 天下滑 / 06 竞品告警
- 06 竞品快照 → Agent 改文案 → 07 扫描 → **Gate 文案** → 01 更新（不自动发布）

### 7.5 WF-PROMO（大促）

- 提前 14 天启动
- 并行：09 大促素材 + 03 广告结构检查 + 02 促销视频
- 多个 Human Gate：价格、素材、脚本
- 大促前 48h 冻结自动 publish

## 8. Human Gate 审批规范

| Gate 类型 | 审批人 | SLA | Reject 后 |
|-----------|--------|-----|-----------|
| 主图审批 | 品牌经理/视觉 | 4h | 重跑 visual 或换参 |
| Listing 发布 | 运营主管 | 4h | Agent 改文案或终止 |
| 达人名单 | 媒介主管 | 8h | 重新 match |
| 独立站发布 | 店长 | 8h | 终止 DTC 分支 |
| 客服回复 | 客服主管 | 2h | 人工接管 05 |

**审批原则**：
- Approve：确认内容可对外
- Reject：必须写意见，便于 Agent 重试
- Edit & Approve：改后放行（改动的 diff 入审计）

## 9. 异常处理

| 异常 | 现象 | 处理 |
|------|------|------|
| E01 下游 07 超时 | scan 步骤 failed | 自动重试 2 次 → 暂停 Run → 人工 scan |
| E02 09 GPU 队列满 | visual  pending >2h | 降级：先用 01 现有图继续；视觉并行 |
| E03 Agent 幻觉文案 | 07 高分拦截 | 降级模型；人工 Gate 必审 |
| E04 误点 Approve | 错误发布 | 01 回滚 SOP；事故报告 |
| E05 Run 僵死 | waiting_human 7 天 | 自动提醒 → 7 天后 auto-cancel |
| E06 工具未注册 | invoke 404 | 架构师补 registry；重跑步骤 |
| E07 Token 爆预算 | 单 Run 超限 | 暂停；主管扩容或简化流程 |

### 9.1 熔断策略

某下游（如 07）连续失败 3 次 → 熔断 15min → 所有 Run 该工具跳过或暂停 → 钉钉 @架构师

## 10. Chat 入口使用规范

**适合 Chat 触发**：
- 「把昨天选的蓝牙耳机上架 Amazon」
- 「检查店铺 A 今日广告异常」
- 「为 SKU-X 匹配 10 个美国达人」

**不适合 Chat（请用固定工作流）**：
- 批量 100 SKU 上架（用批量 WF + CSV）
- 财务结算
- 规则库修改
