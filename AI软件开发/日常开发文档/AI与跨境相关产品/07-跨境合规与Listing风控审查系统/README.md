# 07-跨境合规与Listing风控审查系统

> **软件登记名**：跨境电商商品信息合规审查与风险预警系统 V1.0  
> **产品代号**：ComplianceGuard / CG-07  
> **版本**：V1.0（文档基线：2026-07）

## 1. 产品定位

面向 Amazon、TikTok Shop、Shopify、Walmart 等跨境平台的 Listing 上架前/上架后合规审查系统。通过**禁词库 + 侵权风险识别 + 平台规则引擎 + 可解释报告**，在商品信息进入运营中台（01）或平台发布前完成风险拦截与整改建议，降低封号、下架、资金冻结概率。

### 1.1 解决的核心痛点

| 痛点 | 现状 | 本系统方案 |
|------|------|------------|
| 禁词误用导致 Listing 下架 | 人工抽查，漏检率高 | 多语言禁词库 + 模糊匹配 + AI 语义审查 |
| 商标/专利侵权 | 法务滞后，事后补救 | 图文侵权初筛 + 风险分级 + 证据链 |
| 平台规则频繁变更 | 运营靠经验，无统一标准 | 平台规则版本化 + 自动同步更新 |
| 整改无依据 | 「感觉不对」难沟通 | 可解释报告：命中规则、位置、建议替换 |
| 与中台割裂 | 合规在 Excel 里做 | Webhook/API 对接 01 运营中台，审查即流程节点 |

### 1.2 产品边界

**做什么：**
- Listing 文本/图片/属性字段的合规扫描与风险评分
- 禁词、夸大宣传、医疗声明、平台类目限制、知识产权初筛
- 批量审查、定时复检、变更 diff 审查
- 可解释 PDF/HTML 报告导出
- 与 01 运营中台、10 多 Agent 中枢的标准化对接

**不做什么：**
- 不做律师意见替代（高风险项标注「需法务确认」）
- 不做全自动上架（始终保留人工确认闸口）
- 不做深度专利数据库检索（仅初筛 + 外链指引）

## 2. 目标用户与角色

| 角色 | 典型岗位 | 核心诉求 |
|------|----------|----------|
| 运营专员 | Listing 编辑 | 上架前一键扫描，快速改稿 |
| 合规专员 | 风控/法务助理 | 规则维护、抽检、审计追溯 |
| 运营主管 | 品类负责人 | 团队合规率看板、拦截统计 |
| 技术集成 | 中台研发 | API/Webhook 嵌入现有上架流 |
| 系统管理员 | IT | 租户、权限、规则库版本管理 |

## 5. 系统集成关系

| 上游/下游 | 系统 | 集成方式 |
|-----------|------|----------|
| 上游 | 01 运营中台 | 草稿保存触发审查；审查通过才允许发布 |
| 上游 | 06 选品情报 | 新品立项时预审查品类限制 |
| 上游 | 09 视觉工厂 | 主图文案同步审查 |
| 下游 | 04 独立站 | 商品页 HTML 合规扫描 |
| 编排 | 10 多 Agent 中枢 | `compliance.scan` 作为标准工具节点 |
| 通知 | 钉钉/飞书/邮件 | 高风险即时告警 |

## 6. 快速启动（研发）

```bash
# 本地开发（示例）
git clone <repo> compliance-guard
cd compliance-guard
cp .env.example .env
docker compose up -d postgres redis minio
npm run migrate && npm run seed:rules
npm run dev
# 控制台 http://localhost:3007
# API http://localhost:8007/api/v1
```

## 8. 关键 KPI（运营视角）

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 上架前审查覆盖率 | ≥ 98% | 经 01 流转的 Listing 必须过审 |
| 高风险拦截准确率 | ≥ 85% | 人工复核确认 |
| 误报率（需运营申诉） | ≤ 15% | 持续优化规则 |
| 平均审查耗时 | ≤ 30 秒/条 | P95 ≤ 60 秒 |
| 整改一次通过率 | ≥ 70% | 建议质量指标 |
