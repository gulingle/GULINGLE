## 2. KPI 体系

### 2.1 北极星指标

**上架前合规审查覆盖率** = 经审查 Listing 数 / 应审查 Listing 数 × 100%  
目标：≥ 98%

### 2.2 运营 KPI 看板

| 指标 | 日目标 | 周目标 | 月目标 | 数据来源 |
|------|--------|--------|--------|----------|
| 审查量 | 按店铺计划 | - | - | 系统报表 |
| 高风险拦截数 | 记录 | 趋势下降 | 误杀率 <15% | issues 统计 |
| 平均整改轮次 | ≤1.5 次/Listing | - | ≤1.3 | scan 历史 |
| 审查耗时 P95 | ≤60s | - | - | 监控 |
| 误报申诉率 | ≤5% | ≤4% | ≤3% | 申诉单 |
| 规则库更新 | - | ≥1 次 | ≥4 次 | rule_sets |
| 定时复检覆盖率 | - | 100% 在售 | 100% | scheduled job |

### 2.3 红灯标准（立即升级主管）

- 单日 BLOCKER 级未处理 > 5 条
- 已发布 Listing 被平台下架且未经过本系统审查
- 规则版本发布后出现拦截率异常上升 > 30%

## 3. 日 SOP（运营专员）

**耗时参考：30–60 分钟/日（按店铺 Listing 量调整）**

| 时间 | 步骤 | 操作 | 产出 |
|------|------|------|------|
| 09:00 | 待办清零 | 打开 01 中台「合规待办」或本系统「高风险队列」 | 当日清单 |
| 09:10 | 处理 BLOCKER | 逐条查看可解释报告，按建议改稿 | 重扫通过或升级法务 |
| 09:30 | 处理 HIGH | 优先改标题/五点 | 风险分 <70 |
| 10:00 | 中低风险批量 | MEDIUM 当日处理；LOW 可周批 | 队列清空 |
| 10:30 | 误报申诉 | 确认误报 → 提交白名单申请（合规审批） | 申诉单 |
| 11:00 | 新稿预审 | 当日新建草稿保存即触发扫描，发布前二次确认 | 无高风险残留 |
| 17:30 | 日终检查 | 确认无未处理 BLOCKER；截图 KPI | 日报一条 |

### 3.1 日 SOP 检查清单

- [ ] 高风险队列 = 0
- [ ] 今日新上架 Listing 均有 scan 记录
- [ ] 误报已登记或已申诉
- [ ] 无法自行判断项已 @合规专员

## 6. 标准操作流程（关键场景）

### 6.1 上架前审查流程

```text
运营在 01 编辑 Listing → 保存草稿
    → 07 自动 scan（Webhook）
    → risk_score < 70：进入「可发布」队列
    → risk_score ≥ 70：阻断发布，展示 issues
    → 运营修改 → 点击「重新审查」
    → 通过后 → 主管可选复核 → 01 发布
```

### 6.2 误报申诉流程

1. 运营在 issue 详情点击「申诉误报」
2. 填写：原因、建议白名单词（如有）、Listing 业务背景
3. 合规专员 24h 内处理：同意白名单 / 驳回并说明
4. 同意 → 租户级或全局白名单（按规则）→ 自动重扫

### 6.3 法务审批流程

- 触发：商标命中、专利关键词、医疗声明 BLOCKER
- 合规专员标记 `legal_review_required`
- 法务/主管 48h 内 Approve/Reject
- Reject → 必须改版，不得强制发布

## 7. 异常处理手册

| 异常 | 现象 | 处理步骤 | 升级 |
|------|------|----------|------|
| E01 审查超时 | scan >2min pending | 1.刷新 2.查队列积压 3.改 async | 技术 >30min |
| E02 01 未触发审查 | 草稿无 scan_id | 检查 Webhook 配置；手动 POST /scans | 技术 |
| E03 大面积误报 | 拦截率突增 | 回滚上一规则版本；暂停 publish | 主管+合规 |
| E04 AI 胡编 issue | 无规则 ID 的 AI issue | 降级 AI 权重；反馈 AI 组 | 技术 |
| E05 图片 OCR 失败 | image issue 缺失 | 改手动文本审查；重传高清图 | 运营 |
| E06 已下架未预警 | 复检未覆盖 | 立即全量 scheduled rescan | 主管 |
| E07 跨站点规则混淆 | DE 用了 US 规则 | 检查 marketplace 参数 | 合规 |

### 7.1 事故分级

| 级别 | 定义 | 响应时间 |
|------|------|----------|
| P0 | 已发布大规模违规导致店铺风险 | 15 分钟 |
| P1 | 审查服务不可用 | 30 分钟 |
| P2 | 单条误报影响上架 | 4 小时 |
| P3 | 报告导出失败 | 1 工作日 |

## 8. 与 01 运营中台协同规范

| 节点 | 01 动作 | 07 动作 |
|------|---------|---------|
| 草稿保存 | 发 `listing.draft.saved` | 创建 scan，回写 score |
| 发布点击 | 检查 `publishable` | - |
| 发布后 | 发 `listing.published` | 存档基准快照 |
| 批量导入 | 批量 webhook | batch scan |

**配置项（01 侧）**：
- `compliance.min_score = 70`
- `compliance.block_on_blocker = true`
- `compliance.require_scan_before_publish = true`

## 9. 培训与上岗验收

### 9.1 运营专员上岗（4 小时）

| 模块 | 时长 | 考核 |
|------|------|------|
| 系统界面与报告阅读 | 1h | 找出一测试 Listing 的 3 个问题 |
| 整改与重扫 | 1h | 将高风险样例改至通过 |
| 误报申诉 | 0.5h | 正确填写申诉单 |
| 与中台联合作业 | 1h | 完成一条真实草稿审查 |
| 红线考试 | 0.5h | 笔试 ≥80 分 |

### 9.2 合规专员上岗（8 小时）

- 禁词库维护实操
- 规则版本发布与回滚
- 法务审批流
- 月度复检与月报

### 9.3 上线验收标准（业务侧）

- [ ] 连续 5 个工作日日 SOP 执行无遗漏
- [ ] 上架前审查覆盖率 ≥95%（爬坡至 98%）
- [ ] 至少完成 1 次规则版本发布演练
- [ ] 至少完成 1 次误报申诉闭环
- [ ] 主管签字确认 KPI 看板可用
